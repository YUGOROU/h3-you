# H3-You

**H3-You turns a person's own footage into a video call with an AI version of them.** One person, one room, one continuous conversation: not a talking-head avatar driven by presets.

The pipeline is person-agnostic. A reference photo sets the person, a voice sample sets the voice, and the room comes from the same footage. The same code path that runs my clone is the one that would run anyone's. It has only been tested on one person so far (me), because that is the only identity I can collect data for, consent to, and review frame by frame.

This repository is the research code behind that. It is not a product, and there is no service you can log into. A short project page with the current status lives at [yugoito.dev/projects/h3-you](https://yugoito.dev/projects/h3-you/).

## The idea

The target experience is the feeling of a video call with the real person: the same face, the same room, natural handheld framing, natural listening, and the ability to be interrupted mid-reply and come back without the video stream restarting.

That decomposes into a pipeline that has to stay coherent end to end:

```
 iPhone / Mac microphone ──► ASR ──► Pi director (text, persona) ──► TTS (native PCM)
                                                                        │
                                                                        ▼
   browser / OBS  ◄── paired A/V over HTTPS ◄── H3 (MiniMax-H3 Ref2VA, H200×2) ──┘
```

Everything in between is where the interesting failures live: the turn state machine, the audio clock, the cancellation path, the reference conditioning, and the delivery of decoded audio and video. Most of the documents in [`docs/`](docs/) are about exactly one of those.

The work is GPU-bound. Every spoken second has to be generated by a video-audio diffusion model (MiniMax-H3 Ref2VA, two H200s in the current setup), and a conversation never stops asking for more. The load is bursty, with a hard deadline on the first frame of each reply.

## Status (2026-11-17)

This is a research log, not a release. The honest summary:

| Area | State |
| --- | --- |
| Personalised H3 generation (reference image + LoRA, H200×2) | Works; a 51.9 s two-turn clip was reviewed by the author as a visual baseline |
| Longer continuous generation | A 98.7 s single clip was generated and reviewed (see [media](#media)); a diagnostic candidate, not the accepted default |
| Real-time supply (generated seconds per wall-clock second) | **Not reached**; the accepted clip was supplied at about 0.91× real time |
| Interruption / cancellation of an in-flight reply | Implemented and proven on CPU and in device-free GPU runs |
| iPhone capture app (`ios/`) | Video-only recording verified on device; audio coexistence with a voice call still experimental |
| Live call over Discord / browser / OBS | Verified once end to end, with known audio-input and stability problems since |
| Automated test suite | About 3,000 CPU tests; see [running the tests](#running-the-tests) |
| People tested | **One**: the author |

Accepted baselines, pinned model revisions, and the current next step are described in [`docs/`](docs/).

## Private working area

The pipeline keeps raw media, generated artifacts, owner locks, and the compute ledger outside the repository. Their location is resolved by [`research/h3_personal/private_root.py`](research/h3_personal/private_root.py) in this order:

1. `H3_PRIVATE_ROOT`: an absolute path, used as-is.
2. `$H3_PRIVATE_BASE/$H3_PRIVATE_SESSION`, where `H3_PRIVATE_BASE` defaults to `~/Downloads/H3Personal` and `H3_PRIVATE_SESSION` to `2026-10-12/production-715`.

The defaults reproduce the layout used during development. If you are reproducing this, set `H3_PRIVATE_ROOT` to a directory you own. The two Swift helpers (`research/play_h3_virtual_audio.swift`, `research/set_h3_virtual_input.swift`) read the same variables. `research/launch_h3_realtime_first.py` finds the Modal CLI through `H3_MODAL_CLI` or `PATH`.

## Running the tests

The Python code has no single locked environment, because different parts need different dependencies. From the repository root:

```bash
# Core CPU suite (stdlib only: no GPU, no network, no devices)
python3 -m unittest discover -s tests -v

# Modules that need httpx / huggingface_hub (launchers, job control)
python3 -m pip install httpx huggingface_hub
python3 -m unittest discover -s tests -v

# WebRTC / RTC modules (aiortc, av) use the isolated experiment lock
uv sync --project research/webrtc_experiment --locked
research/webrtc_experiment/.venv/bin/python -m unittest discover -s tests -v

# Director contract tests (Node)
for f in tests/*.mjs; do node --test "$f"; done
```

The suite is split by dependency, not by importance. With the core interpreter alone, the launcher, job-control, and WebRTC modules report import errors and the rest passes; CI runs exactly that core set (any `ERROR:`/`FAIL:` line fails the job) plus the Node contract tests.

A few Zoom/VoxLock tests import numpy; [`tests/_numpy_shim.py`](tests/_numpy_shim.py) provides a stdlib-only stand-in, so a clean checkout runs without numpy installed. Two timing-sensitive tests (`test_input_is_stopped_before_joining_blocked_sender`, `test_generator_failure_reaps_idle_sender_and_ack_reader`) occasionally fail under load and pass on rerun; this is a property of the tests, not of the pipeline.

The iOS app builds and tests on macOS without a simulator:

```bash
xcodebuild -project ios/H3Camera.xcodeproj -scheme H3Camera \
  -destination 'generic/platform=iOS' -derivedDataPath /tmp/h3-camera-build \
  CODE_SIGNING_ALLOWED=NO build
xcodebuild -project ios/H3Camera.xcodeproj -scheme CoreTests \
  -destination 'platform=macOS' -derivedDataPath /tmp/h3-camera-tests test
```

## What this repository deliberately does not contain

- No recordings, personal audio, reference photos, LoRA weights, or generated clips, except the single reviewed demo clip in `docs/media/`.
- No API tokens, signing credentials, or developer-team identifiers.
- No cloud launcher that starts a GPU job by itself: GPU entrypoints default to an offline preflight and require an explicit `--run` or `--submit`.

Everything under `research/` that talks to Hugging Face Jobs, Inference Endpoints, or a local device is written to fail closed, and the documents in `docs/` describe the approvals each one needs. Working notes, failed attempts, dated reports, and budget ledgers are kept locally instead of here: see [`research-log/README.md`](research-log/README.md) for how that line is drawn.
