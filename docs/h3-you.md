# Personalized Streaming H3 — Research Plan v0.3

更新: 2026-10-11  
ベース: `personalized_streaming_h3_research_plan_v0.2.md`

## 0. 研究目的と基本方針

**MiniMax-H3を本人専用のリアルタイム動画会話モデルへ適応する。** 主な体験は、**自宅での会話**と**iPhoneを持って歩きながらの会話**。本人らしい外見・声・自然な会話の流れを維持し、背景やカメラ画角が自然に変化しても映像の綻びが生じないことを目指す。

- 映像: MiniMax-H3 Ref2VAを主軸。特にiPhone Selfieでの姿勢・手持ち視点・背景変化という表現自由度を維持する。
- 音声・対話: VoxCPM2を音声生成の第一候補、LLM Agentで会話内容・発話/傾聴・割り込みを制御。LLMのSFTは初期スコープ外。
- 収録: ChatGPT iOS Voiceを会話相手とし、自作SwiftカメラAppで**インカメ映像を独立収録**する。Mac撮影も維持。
- GPU: 稼働単価 **$10/hr以下**、実験全体 **$100–150**（計画額$140）。iOS App開発自体は原則クラウドGPUを使用しない。
- 優先: 自然な会話 → 本人らしさ → 長期映像一貫性 → 実時間性 → 背景・画角の自由度。
- 初期デモ: Webでの会話。ネイティブiPhoneアプリのLINE/Discord映像入力差し替えは別課題。

## 1. 背景の扱い（今回の変更点）

**主たる評価対象は、実在建物の厳密な復元ではなくSpatial / Temporal Consistency。** 一度映った背景が、顔や空しか映らない時間を挟んでも、再び見えるときに形・相対位置を保っていること。架空の背景でも成立する必要がある。

- 回転、歩行、視点移動は**収録に自然に含める**。カメラ運動だけを主題にした反復訓練や細かい動作シナリオは作らない。
- 主要な行動は、家での普段の会話と、普通に歩きながらの雑談・傾聴。
- **360°背景パノラマはオプションの推論時Reference。** 実在環境を条件付けたい場合に、セッション開始時の周辺画像を渡すことを構想する。任意背景の安定性にはReference必須としない。
- 1枚の360°画像だけでは歩行時の視差を完全に記述できないため、モデルの継続生成能力・シーン記憶で不足を補う必要がある。
- パノラマを使う場合、まず**自分で撮影した素材**を使用する。Google Street Viewのコンテンツを無許諾で学習・テストに流用しない。

## 2. Phase 0 — 学習なしPoC（GPU計画 $20）

**実験A：本人の音声駆動動画**

本人Selfie参照と本人WAVを、H3 Ref2VA + 互換のある高速化LoRAに渡して短い動画を生成する。本人らしさ、発話同期、背景の自然さと概算生成速度を見る。

**実験B：連続生成**

同一人物・同一シーンで複数区間を継続生成し、顔と背景の再出現、接続部の綻び、生成速度を観察する。

PoCはこの2実験だけ。詳細なベンチマークや比較は失敗箇所が判明してから行う。速度不足は以後の研究課題として扱う。

## 3. Phase 1 — 本人データ収集（最初からフルサイズ）

**目標：本人映像120分程度 + 別録りの高品質な本人音声20分程度。** 初期Pilotフェーズは挟まない。

| 区分 | 目安 | 主な内容 |
|---|---:|---|
| iPhone Selfie | 80分 | **自宅**と**屋外の散歩**。自然な発話・傾聴・沈黙・歩行・持ち替え・周辺を見る動作 |
| Mac Front Camera | 40分 | **自宅通話**。着席した会話・考える動作・視線・姿勢・照明の自然な変化 |
| 本人の音声（別収録） | 20分 | クリアな声、通常の雑談、笑い、言い直し、話し方の変動 |

### 収録方針

- 場所のリストやセッション単位の時間割は固定しない。**自宅 / 外**を大きな分類とし、日常的な通話の中で長回し収録する。
- 時間帯・天気・服装・背景・照明は異なる機会で自然に増やす。全組み合わせの網羅は不要。
- 立ち止まる、道を曲がる、顔の画角が変わる、背景のみ映る、再び同じ背景が見える——こうした変化は普通の散歩中に含まれればよい。
- **発話中と傾聴中の映像を両方確保**する。会話として自然な比率を優先し、撮影のための不自然なカメラ操作は増やさない。
- 原本を保存し、学習用の短い動画や24fps変換は後処理で作る。分割はセッション単位で行い、隣接クリップのTrain/Test漏洩を避ける。
- メタデータは最低限 `session_id, device, indoor/outdoor, datetime, video, audio_source` 程度。天気・服装などは必要に応じて追加。
- **本人映像に同期した発話音声が必要なサンプルは、音声を必ず別途確保する。** ChatGPTとの会話テキストだけではLip-syncや発話動作の教師信号の代替にならない。
- 第三者の顔・声・私的情報をなるべく入れず、必要な同意を得る。元データはprivate管理。

### iPhone収録方式

1. ChatGPT iOS Voiceで会話を開始し、「Background Conversations」を有効にする。
2. 自作カメラAppを**フォアグラウンド**で開き、ChatGPTとの会話を続けながらインカメ映像を撮る。
3. カメラAppが同時にマイク録音できる場合だけ、本人発話を同期収録する。ChatGPT Voiceと衝突する場合は**映像のみ収録を優先**し、必要な本人音声は別端末で同期収録する。
4. 撮影動画と必要に応じた音声をMacへ移し、セッションとして保存する。

**技術上の未確認点**：ChatGPT Voiceがバックグラウンドで動作することと、別Appから同じマイク入力を同時取得できることは別。実機で両立を確認するまで音声の二重取得を前提にしない。録画Appをバックグラウンドに移したまま撮影することも要件にしない。

## 4. Swift製iPhoneカメラApp — 要求仕様

**役割：ChatGPT Voiceの会話を邪魔せず、本人のSelfie収録データを確実に保存する最小限の専用ツール。** UIやフレームワークの細部、クラス設計、保存実装方式は実装エージェントの裁量とする。

### Must have（必須）

- [ ] **ChatGPT Voiceのバックグラウンド会話と両立**する。アプリ起動、プレビュー、録画開始/終了によってChatGPT側の発話・聴取を不必要に中断しない。
- [ ] **フロントカメラ映像をローカル動画ファイルに録画**できる。自然なSelfie画角・カメラ向き・回転を保持。
- [ ] 音声の占有競合がある環境では、**音声なしでも映像だけを録画**できる。
- [ ] 少なくとも**1080p/30fps相当を目標**に、長時間の収録（10〜30分程度）を安定して行う。非対応時には適切なフォールバック。
- [ ] 撮影の開始/停止、プレビュー、録画時間・録画状態・保存完了/失敗を明瞭に表示。歩行中に操作を増やさない。
- [ ] 保存した動画をMacへ簡単に取り出せる。ファイル名または付随情報で撮影日時・Sessionを追跡できる。
- [ ] 音声/カメラの割り込み、ストレージ不足、アプリ異常などで、可能な限り録画済みデータを失わない。
- [ ] 必要最小限の権限と端末内保存を基本とし、勝手にクラウドアップロードしない。

### Should have（可能なら）

- [ ] **ChatGPT Voiceと共存できる場合のみ**、本人の声を動画と同期して収録。できない場合は機能を無効化し、会話維持を優先。
- [ ] 別端末で録った音声との同期に使える撮影開始時刻・録画タイムスタンプ。
- [ ] 縦/横画角への柔軟な対応と撮影設定の最小限の切替。
- [ ] 長時間撮影時の容量・電池/発熱などの簡易的な状態表示。

### Non-goals（作らないもの）

- ChatGPT Voiceの制御、会話UIやLLM API連携、音声の抜き出し。
- 独自のビデオ通話アプリ、配信・編集・自動ラベリング機能。
- カメラ姿勢の3D追跡、背景のSLAM/再構成、360°パノラマ生成。
- iPhoneカメラApp自身のバックグラウンド撮影やApp Store公開のための追加機能。

### 最初の受け入れ条件

1. 実機iPhoneでChatGPT Voiceを開始し、Camera Appへ切り替えたあとも**双方向会話が継続**する。
2. 会話しながら少なくとも**10分のインカメ動画**を録画・正常保存し、途中の停止、重大なドロップ、破損がない。
3. マイクを使わない動画収録とChatGPT Voiceの同時動作が成立する。本人音声も収録できれば追加成果とし、不可なら外部収録へ切り替えられる。
4. 保存した動画がMac側で問題なく扱え、収録日時・長さが分かる。

## 5. Phase 2 — Streaming実装（GPU計画 $30）

`Mic → VAD/ASR → LLM Agent → VoxCPM2 → H3 Ref2VA → A/V Sync → WebRTC`

短い音声chunkから過去latentを保ちつつ動画を継続生成。発話/傾聴/割り込みを扱い、音声と映像の同期を取る。長時間の背景一貫性は本研究の品質要件。実装の目的から外れる詳細なサブシステム分割はしない。

## 6. Phase 3 — 個人特化学習・高速化（GPU計画 $70）

1. H3本人LoRAを既存Trainerを使って学習し、顔・表情・Selfieの自然な振る舞いを改善。必要ならVoxCPM2も本人音声へ適応。
2. Ref2VA互換の高速化を踏まえて、必要な箇所へ量子化/Pruning/Distillationを行う。
3. 短窓での継続性や一貫性が不足する場合にCausal AdaptationとScene Memoryを検討する。

LoRAだけで推論コストが自動的に下がるわけではない。広範な探索より、観測した失敗を修正する一手を優先する。

## 7. Phase 4 — 比較・評価（GPU計画 $20）

原則「元のH3 Ref2VA」と「最終的に適応したH3」の比較のみ。

- 本人らしさ：同一音声・同条件で、顔・声・自然な傾聴と身振り。
- 映像の一貫性：背景・顔が見えなくなって再出現した際の安定性（架空/実在どちらも許容）。
- 自由度：自宅/散歩、照明・服装・背景変化、自然な移動に対応できるか。
- 推論性能：起動後の初回フレーム待ち、持続生成速度、途切れ、GPU実費。
- チャレンジ目標：24fps相当での継続出力、生成速度が再生速度以上、低遅延の会話。

## 9. 直近の行動

Swiftカメラを `ios/` に実装済み。初期設定は映像のみで、任意のiPhone内蔵マイク録音・経路診断の実験モードを追加。ビルド・テスト結果と実機受け入れ手順は [ios-camera.md](ios-camera.md) を参照。**映像専用モードで、ChatGPT Voiceのバックグラウンド会話 → 録画・保存 → Mac転送・プレビューまでユーザー実機確認済み。10分以上の連続録画は時間の報告待ち。次はSoundcore A25i出力＋iPhone内蔵マイクの同期音声収録について、経路と同時入力の共存を検証する。**

1. Swift製Camera Appを実装し、**ChatGPT Voiceを中断しないインカメ録画**ができるか実機確認。
2. 同時音声収録の可否を判断。両立できない場合には本人発話用に別端末の録音を併用。
3. 自宅通話・散歩通話を自然な形で収録し、120分の本人データセットへ。
4. 研究本体はv0.2のPhase 0 → Streaming → 学習 → 比較の順で進行。
